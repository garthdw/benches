# Backend (macOS) and pipeline requirements

The backend lives in the `rune-gpu` crate (`crates/rune-gpu/src/metal/`), reached through `rune`'s re-exports (`rune::GpuBackend`, `rune::describe_gpu`). Benches takes Rune's defaults, so `metal-backend` is on and nothing calls `App::gpu_backend` or sets `RUNE_GPU_BACKEND`: it runs on **Rune's native Metal backend**, not wgpu-hal. It plugs in through wgpu's `custom` backend, so `f.device`/`f.queue`/`RenderPass` are ordinary wgpu types and render.rs needs no change. The adapter reports `Backend::Metal`, driver `"rune metal"`. `rune::describe_gpu(f.device)` names the backend and why; `RUNE_GPU_LOG=1` prints it per window.

- **OS floor:** the native backend runs only from macOS 13 (it writes MSL 3.0); older systems draw with wgpu, even under `RUNE_GPU_BACKEND=metal`. The bundle's `LSMinimumSystemVersion` is 13.0, so a bundled Benches always gets the native backend.
- **Headless `--snap`** uses `Gpu::headless()`, the same native backend, so snaps exercise the same path as the window. With a compositor attached, each headless frame waits for the GPU to finish before the next.
- **Fallback:** if `features()` asks for anything beyond `TIMESTAMP_QUERY | IMMEDIATES` (the native set) and the backend is only the default, Rune logs once and draws with wgpu instead. An explicit `RUNE_GPU_BACKEND=metal` skips the fallback.
- **Switch to wgpu-hal** to compare or debug: `RUNE_GPU_BACKEND=wgpu cargo run` (env beats `App::gpu_backend`).
- **WGSL only:** naga translates each entry point to MSL per pipeline. Other shader sources panic. WGSL that naga rejects panics in `create_shader_module` with the module's label and the naga message.
- **Resource lifetime:** command buffers hold unretained references, but the backend keeps every texture, buffer, bind group and drawable they use alive until the GPU completes that buffer. So dropping a resource right after recording a draw with it (the atlas `grow` swap, `ImageTextures::sweep`) is safe.
- **Unsupported, panics** naming the way back to wgpu: depth/stencil, multisampling and resolves, more than 4 colour attachments, more than 8 bind groups, binding arrays, render bundles, indirect draws, query sets (except `TIMESTAMP_QUERY` at pass boundaries), `clear_texture`, `Queue::write_buffer_with`. Benches uses none; the quad pass is plain instanced triangles.
- **Formats/sRGB:** no change to the sRGB rules in `SKILL.md`. The frame target and layer formats come from Rune; Benches builds its pipelines per `site.format`; its glyph atlases are `R8Unorm` (coverage) and `Rgba8Unorm` (colour).
- **Buffers** are shared-storage and CPU-written in place; `Frame::write_buffer` and `Queue::write_buffer` both work, the former avoids an extra command buffer. `IMMEDIATES` (per-draw bytes up to 4 KB) is available if `features()` requests it.
- **Lost device:** any command buffer that ends in error (a GPU hang or timeout, a buffer discarded during the GPU's recovery, a removed device) loses the device, as in Dawn. The lost callback runs first, then every pending work-done callback, and buffer mappings fail with `BufferAsyncError`. Rune's `Gpu::is_lost` turns true, and the window's next draw replaces the surface, device and `Renderer` (`Host::replace_lost_surface`), so the compositor sees a new `device_key` and rebuilds. Frames recorded on the lost device never show. Losses are counted per mode with one forgiven every 5 minutes: 3 on the hardware adapter switch an automatic pick to a software one, and 3 more give the window up (`AppHandle::window_error`). The doc comment in `render/gpu_loss.rs` saying the Metal lost callback is a no-op is stale.
- **Lost device on wgpu:** Benches patches in Rune's vendored wgpu-hal (`Cargo.toml`), so under `RUNE_GPU_BACKEND=wgpu` a Metal hang loses the device too.

## Pipeline requirements in Benches

Instanced `TriangleStrip`, 4 vertices, one per-instance vertex buffer (`Quad`). Per format there are two pipelines on one WGSL module: cells (`fs`, bind group 0) and images (`fs_image`, group 0 plus group 1: the image texture and its sampler). Group 0 holds the uniform (binding 0), the colour atlas (1), a filtering sampler (2) and the coverage atlas (3). Each `PipelineLayoutDescriptor` lists its groups as `Some(&layout)` with `immediate_size: 0`, and `RenderPipelineDescriptor` needs `multiview_mask: None`, `cache: None` on this wgpu version.
